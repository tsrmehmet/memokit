# Changelog

Every change to `hooks/`, `skills/`, `agents/` or `WORKING-MODEL.md` bumps `version` in `.claude-plugin/plugin.json` and adds an entry here (a pinned version means `/plugin update` delivers nothing otherwise).

## 0.7.0 — 2026-10-20
- **Adopt mode** (user decision): `/memokit:init` now adopts a project's existing AI setup instead of only migrating legacy hooks. `detect` reports `aiSetup`, `sources` and `inventoryError`; a new read-only `inventory` subcommand lists CLAUDE.md, AGENTS.md, other tools' rules (Cursor, Copilot, Windsurf, Devin (`.devin/rules`), Cline, Roo, Gemini, Kiro, Continue, Junie, Zed, Aider), `.claude/` agents/skills/commands/rules and project hooks with their group, tracked/ignored state, symlink target and frontmatter. `remove` (git rm of tracked, clean paths) and `settings --drop-hook <event> <substring>` (drops the hooks of `<event>` whose command contains `<substring>`, exit 3 when nothing matches; refused together with `--drop-legacy-hooks` or with an empty substring) are new. Nothing is written before the user approves one table; one commit, only after the diff is approved.
- User decisions: Claude-owned sources are moved, other tools' files stay byte-identical (content copied with a `(source: <path>)` tag); `AGENTS.md` is never edited, `CLAUDE.md` imports it with `@AGENTS.md` and carries an override section for conflicting items; scoped rules go to `.claude/rules/` with `paths:`; conflicts have no keep option (accept or cancel); the legacy migration is folded into adopt mode (README section renamed "Adopting an existing AI setup").
- [call]s: a legacy setup is recognised by the memokit `inject-rules.sh` signature (`inventory .legacy` is non-null only when `extract-legacy` finds a tag); a project's own `.claude/hooks/` is ordinary project hooks, while `detect.legacy` stays directory-based. Symlinked directories are listed, not followed. A hook's `scriptPath` must resolve physically inside the project root. The skill keeps `rules.md` to about 1.5 KB (guidance, not enforced) because it is appended to every prompt; longer rules go to `.claude/rules/`. When `scriptPath` is null (`bash x.sh`, `FOO=1 x.sh`) the skill reads the hook `command` itself.
- `inventory` also reports `settingsTracked`/`settingsIgnored` and lists non-command hooks (`type: "prompt"`, `command: null`); `remove` refuses the project root (`.`, `./`). With legacy hooks, edits under `.claude/agents|skills|hooks` and `.claude/settings.json` are written after `remove-legacy`; when `settings.json` is git-ignored or untracked, the skill does not run `--drop-hook` (the script itself does not check this): the row tells the user to drop the hook by hand, since `git revert` cannot restore that file.
- **Plugin registration is opt-in** (user decision, from an adopt trial on an open-source repository): `/memokit:init` asks whether everyone who clones the repo should be offered memokit (recommended no unless the user maintains it and the team agreed) and only on yes runs `settings` without flags, which writes `enabledPlugins` and the `tsrmehmet/memokit` marketplace into the shared `.claude/settings.json`. `settings --drop-hook` and `--drop-legacy-hooks` (so `remove-legacy` too) no longer add that registration, and `--drop-legacy-hooks` creates no `settings.json` when there is none. A user-scope install already enables memokit for its user; the shared entry would offer every contributor an unpinned third-party plugin whose hooks run shell commands.
- Tests: new end-to-end cases in `tests/init-adopt.bats` (other-tool files and hooks byte-identical; real legacy project in the SKILL's order).

## 0.6.2 — 2026-10-20
- **Install once, at user level** (user decision): the manifest now sets `"defaultEnabled": true`, so `claude plugin install memokit@memokit --scope user` leaves memokit enabled for every project (measured: with `false` the same install wrote `"memokit@memokit": false`). The README no longer warns against user-level enablement; the hooks still act only where `.claude/memokit.json` exists, and the `memokit:`-namespaced agents and skills stop without it. `/memokit:init` still writes `enabledPlugins` and the marketplace into the project's `.claude/settings.json`, so a clone turns memokit on too.
- The SessionStart "run `/memokit:init`" hint is **off by default**; `MEMOKIT_INIT_HINT=1` turns it on. The pre-0.6.2 `MEMOKIT_NO_INIT_HINT=1` is still honoured and wins.
- Scripts named in `memokit.json` (`sessionStart.healthScript`, `graph.refreshScript`) must stay inside the project root: a path whose directory resolves elsewhere (`../`, a symlinked directory) or that is itself a symlink is not run; session start says so, and `memokit-graph.sh refresh` exits 2. The README tells users to look at `.claude/memokit.json` in a repository they do not trust (same exposure as hooks in its `.claude/settings.json`).
- Tests: the suite drops every inherited `MEMOKIT_*` variable, so a developer's own setting (e.g. `MEMOKIT_NO_INIT_HINT=1` under `env` in `~/.claude/settings.json`) no longer turns hint tests into false passes.

### Upgrading from a per-project install
- Install once with `claude plugin install memokit@memokit --scope user`. Existing `--scope local` installs keep working; to drop one, run `claude plugin uninstall memokit@memokit --scope local` from **that project's root**: it edits the `.claude/settings.local.json` of whichever project contains the current directory, so diff that file before and after.

## 0.6.1 — 2026-10-20
- **Auto-clean at session start** (user decision): stale temp entries of earlier sessions (older than `scratch.staleAfterHours`, accepted by the same check the guard uses for a whole stale sibling, nothing under them holding `.memokit-keep`) are removed in a detached background job, and the session start says so in one line. Leftover worktrees are checked by a detached job too (it needs a status per worktree, which the hook must not wait for): `merged-clean` worktrees that look unused for `scratch.staleAfterHours` (index not rewritten, no Claude Code transcript for that path written, no process with its cwd inside, per `lsof` when present) and still show no change and no ignored file right before the removal are removed with `git worktree remove` (never forced; an `mk/*` branch then with `git branch -d`; needs git ≥ 2.31), and merged `mk/*` branches without a worktree with `git branch -d`. Dirty, unmerged, `merged-ignored` (a `.env`, build output), in-use, `manual` and `active-run` rows stay for the user: once a check has run, every session start reports them with `/memokit:sweep worktrees`, as before (the check itself reruns at most once an hour). `MEMOKIT_AUTOCLEAN_OFF=1` restores report-only.
- Destructive-command guard: a recursive `rm` of a scratchpad path inside a compound command (`&&`, `;`, a variable) is still denied, but the message now tells the agent to re-run it as its own `rm -rf <literal absolute path>` call, which passes without approval, instead of only "ask the user". In October 2026 transcripts 140 of 146 such chained cleanups were denied and then abandoned, which is why subagent temp piled up.
- `/memokit:init` asks whether the project needs the Artifact tool (HTML pages such as UI mockups) and, if not, denies it in the git-ignored `.claude/settings.local.json` through the new `memokit-init.sh deny-tools <root> <tool>...` (bare tool names only, merged without duplicates, the file git-ignored when it is not already).
- Parallel runs: a ledger whose status line is spelled `Status:` or is the last line without a newline is recognised as active.
- `/memokit:parallel`: after `add -N` a resolution slice's conflicted files show as `DA`; the skill now says so.
- Upgrade note (0.6.0): the scaffold command is given with the plugin-cache path for your own shell, and says to review `git status` afterwards.

## 0.6.0 — 2026-10-19
- `/memokit:parallel`: runs a batch of independent tasks in parallel lanes, each in its own git worktree (`.claude/worktrees/mk-<run>-<lane>` on `mk/<run>/<lane>`, created from the current integration branch; nothing untracked, ignored or secret is copied in). Analysis → plan approval (lanes, solo lanes for hotspots, risk tags) → one batch decision sweep (at most 4 questions per prompt) → rolling lanes up to `parallel.maxCoders` (a runtime decision pauses only its lane) → review by risk → merge queue in completion order with a Tier-1 re-run after each merge (conflicts and reds go to a resolution slice; leftover conflict markers are grepped in the files that had conflicts) → cleanup by measurement (`git worktree remove`, `git branch -d`, never forced) → Opus batch review → the Tier-2 question. A git-ignored, local ledger (`.claude/memokit/runs/<run-id>/ledger.md`) records every state (`planned` → `decided` → `running` ⇄ `needs-decision` → `in-review` → `approved` → `merging` → `merged` → `done`), so a compacted or new session resumes the run; the run ends with per-lane token totals and wall time.
- New agent `memokit:analyst` (Sonnet, read-only with every tool, MCP included): touched files, dependencies, a `high`/`normal` risk tag and decision questions with recommendations; project overlay `.claude/memokit/analyst.md`.
- Test tiers, a general rule (WORKING-MODEL.md §9, re-injected on every prompt): Tier 1 (build, unit tests of the touched projects, the slice's new tests) in every slice; Tier 2 (integration, coverage, merge gate, E2E) once per batch, only after the user's explicit go, run by the orchestrator one gate at a time. A green Tier 1 is `gate-pending`, never done. Commands live in the new overlay `.claude/memokit/gates.md`; when it is missing the coder returns `BLOCKED` and the orchestrator asks once.
- `memokit:coder` returns `DONE`, `NEEDS_DECISION` (one question in §2 format) or `BLOCKED`, runs Tier 1 only, and works only in the directory its brief names. Agents accept their overlay as text in the brief and report `brief text` in the overlay line.
- Reviewer by risk: `memokit:reviewer` stays one agent; in a parallel run `review.model: auto` reviews `high`-risk tasks on Opus and `normal` ones on Sonnet, a Sonnet reviewer answers `ESCALATE: opus — <reason>` on a high-risk concern, and one Opus batch review always runs before the Tier-2 question.
- Design quality (WORKING-MODEL.md §8): SOLID applied pragmatically, balanced by KISS/YAGNI; the reviewer rejects both SOLID violations that matter and over-engineering, with `file:line`.
- Config: new `parallel` (`maxCoders` 3, `maxReviewers` 3; integers ≥ 1) and `review` (`model`: `auto` | `opus` | `sonnet`) settings.
- Destructive-command guard: `git worktree remove --force`/`-f` is denied with the approvable label `git-worktree-force` (it can discard a worktree's uncommitted work); plain `git worktree remove` and `git branch -d` stay allowed.
- Leftover worktrees: SessionStart reports the worktrees under `.claude/worktrees/` (lanes and Claude Code `agent-*` worktrees) of the main checkout and of every other worktree of the repository, and `mk/*` branches without a worktree, in one line with their total size (bounded to about 2 s, the session's own worktree excluded; under 1 MB in KB). Lanes of a run whose ledger says `status: active` are not leftovers: they get a separate line naming the run, which `/memokit:resume` continues, and `/memokit:sweep` lists them as `active-run`, never offered; a run the user ends early is `status: stopped` and its lanes are reported like any others. `/memokit:sweep worktrees` lists them with status and merged-into (current or default branch), offers only `merged-clean` rows, takes a `merged-ignored` row only by an explicit pick, lists branches merged only into the default branch for deletion from there, and never removes unmerged or dirty work; the nested-repo check runs `find` only on ignored directories.
- `/memokit:init` scaffolds `analyst.md` and `gates.md` and ignores `.claude/memokit/runs/` and `.claude/worktrees/`; `/memokit:handoff` stops running agents cleanly, updates the ledger and writes "Resume run <id> with /memokit:parallel" as STATE's next step; `/memokit:resume` continues an active run through `/memokit:parallel`, and before the first coder slice asks once for the Tier-1/Tier-2 commands when `gates.md` has none.
- Lane review sees new files: at the DONE check the orchestrator marks the lane's new files intent-to-add (`git -C <wt> add -N -- .`, nothing committed), so `git diff HEAD` and its `--stat` include them. Merges use `git merge --no-ff --no-edit` (or `-m` with the overlay's message conventions); the conflict-marker check also catches diff3 `|||||||` lines; the run's end commits `docs/STATE.md` with a pathspec.

### Upgrading from 0.5.x
- **Test commands move to `.claude/memokit/gates.md`.** Every coder slice, sequential ones too, now takes its commands from `gates.md` and returns `BLOCKED` (`gates.md missing`) until it has a Tier-1 command; the coder no longer reads test commands from `coder.md`. Move them from your `coder.md` overlay into `gates.md`: build and unit tests under `## Tier 1`, integration, Docker/Testcontainers, coverage, merge gate and E2E under `## Tier 2`. Or leave it to the next session: `/memokit:resume` sees test commands in `coder.md` with no Tier-1 command in `gates.md`, proposes the move and asks you once.
- **Drop per-slice heavy gates from `coder.md`.** A `coder.md` that asks for integration or Docker runs in every slice now conflicts with the coder's Tier-1-only rule: the heavy gates run once per batch, after your go.
- **New overlay skeletons.** `/memokit:init` stops on a configured project, so run its scaffold step directly. Ask Claude in the project to run it, or in your own shell (where `CLAUDE_PLUGIN_ROOT` is not set) use the plugin cache: `bash ~/.claude/plugins/cache/memokit/memokit/<version>/skills/init/scripts/memokit-init.sh scaffold <project root> <tr|en>`. It adds the missing `analyst.md` and `gates.md` skeletons without overwriting any existing file; it also creates any other missing scaffold file (e.g. `docs/DECISIONS.md`), so review `git status` afterwards and delete what your project keeps elsewhere.
- **Ignore lines.** `.claude/memokit/runs/` and `.claude/worktrees/` arrive through `/memokit:init` on a new project, or through the first `/memokit:parallel` run, which adds them idempotently and commits only `.gitignore`.

## 0.5.3 — 2026-10-18
- Hooks no longer write `printf: write error: Broken pipe` to stderr when SIGPIPE is ignored (GitHub Actions): `grep -q` may stop reading at its first match, so the feeding `printf` is now quiet. This made the CI test "deny message lists every label" fail; the guard's decision was not affected. The pathological-input test keeps the 1 s target as a report and asserts < 3 s (inside the 5 s hook timeout) so a slow runner does not flake.
- Destructive-command guard: the case normalisation of command names in the flat view no longer skips a word right after another one (`echo rm;RM -rf x`, `true;Git push -f`, `a|RM -rf x`, `RM RM -rf x` were not labelled): the lowercasing expressions match only the leading boundary, so no separator is consumed.

## 0.5.2 — 2026-10-18
- Destructive-command guard: a quoted, escaped, prefixed or grouped command word no longer bypasses the rules (`"rm" -rf src`, `r""m`, `\rm`, `sudo rm`, `timeout 5 rm`, `{rm,-rf,src}`, `(cd src && git reset --hard)`, `git push -f&`, zsh `/bin/rm(N)`, `rm>/dev/null -rf x`). Every rule now also runs on a flat view of the command built in one linear `sed` pass (quotes and backslashes deleted, `( ) { }` and backticks blanked, glued `; | & < >` split); labels are only ever added.
- A computed command word right before an rm-style recursive option (`$RM -rf x`, `${RM:-rm} -rf x`, `/bin/r? -rf x`) counts as a recursive rm, without the build-directory safelist.
- Unique abbreviations count: `git push --fo…`, `git clean --fo…`, `git reset --ha…`, `rm --r…`; `helm un|del` and `docker volume remove` are matched.
- Fail closed, in bounded time: a command longer than 64 KiB, or with more than 1000 distinct rm segments, is denied as `too-large` (approval code still works); a flat view that cannot be built is denied as `unparsed`. `too-large` never hides `careful-state`: a big command that touches the approval file is still denied without an approval code. Every stage of the check fails closed: an awk, sed, grep, tr or jq that fails or prints nothing gives `unparsed` (the next stage falls back to the unprocessed text, a grep error counts as a match), careful-state is checked first, and labels are de-duplicated without awk. The guard checks labels in bash (a broken grep no longer reads as "no careful-state"), validates jq's deny and config output, and a tr or grep that fails or prints nothing gives careful-state. More spellings: wrapper `-n` (`nice -n 10 git clean -fdx`), command names in any case or with `.exe` (`RM -rf x`, `Git push -f`, `kubectl.exe delete`), `dropdb`, `mysqladmin … drop`, `pgcli`; `__pycache__` and `.pytest_cache` join the rm safelist. `git clean -f` is labelled even with `-n`/`--dry-run` (an option argument such as `-e -nx` read as a dry run let `git clean -fdx -e -nx` through). The grant-file check is case-insensitive and glob-aware: the name (`CAREFUL-GRANTS`, `careful?grants`, `careful*grants`) is never approvable, nor is a glob on a temp-located `memokit-` path (`/tmp/memokit-*`, `$TMPDIR/memokit-*`); other globs (`careful*`, `../memokit-*`) are the approvable `careful-state-glob`; every deny message lists all labels; and each awk/sed stage must echo a per-call sentinel line, so a tool printing plausible but constant output fails closed. The temp exemption skips commands over 4 KiB (1 KiB with a line continuation), which removed a quadratic slowdown that let the guard run past its 5 s timeout on 64 KB of continuations.
- Known false positives (accepted, ask for approval): quoted text is matched like a command (a commit message mentioning `git push --force` now asks too), and `"$EDITOR" -R file`-style computed words before an `-R`/`-r` option. Still out of reach (README, Limitations): `$X push -f`, `$(printf %s r m) -rf x`, `/bin/r(m|x)`, `$RM src -rf`, `DROP${IFS}TABLE`.

## 0.5.1 — 2026-10-18
- Linux portability: the `human_kb` test no longer fails on hosts without the `tr_TR.UTF-8` locale (bash's setlocale warning leaked into the captured output); no awk/mawk difference was found in the 0.5.0 code.
- shellcheck compatibility: `A && B || C` chains in `careful.sh` and `temp.sh` are explicit `if` statements, so older shellcheck releases (SC2015) pass.

## 0.5.0 — 2026-10-18
- Subagent temp-footprint gate: new SubagentStop hook `check-subagent-scratch.sh` blocks (up to 3 times) a subagent that leaves `scratch.agentMaxMB` (default 1024) or more of new files in the session scratchpad. `MEMOKIT_SCRATCH_OFF=1` disables it.
- Disk watch: new hook `check-disk.sh` (PreToolUse, PostToolUse and PostToolUseFailure on Bash, and Stop) warns when one command, failing or not, drops free space (min of the project and temp-root filesystems) by `disk.dropWarnGB` (10), warns below `disk.minFreeGB` (30; 0 = off), and at Stop points to `/memokit:sweep`. `MEMOKIT_DISK_OFF=1` disables it; SessionStart reports large temp leftovers (`scratch.reportMinMB`) and low disk.
- Config: new `scratch` (`agentMaxMB`, `staleAfterHours`, `reportMinMB`) and `disk` (`minFreeGB`, `dropWarnGB`) settings.
- Temp rules: WORKING-MODEL.md §7 (shell-agnostic copy recipe with literal `<paths>`, one scratchpad dir per task, delete before returning, `temp left:` line), the injected rule block and the `memokit:coder` / `memokit:reviewer` agents carry them.
- Destructive-command guard: recursive `rm` needs no approval only for a single simple `rm` of a literal direct child of the current session scratchpad or a whole stale sibling temp entry; commands containing NUL are denied.
- `/memokit:sweep`: measures stale temp leftovers, asks, deletes the approved ones one literal `rm -rf` at a time and reports the freed space.
- Destructive-command guard fixes (made after 0.4.0): backslash line continuations are joined before matching, SQL heredocs are flattened, and grant temp-file hygiene.

## 0.4.0 — 2026-10-06
- Destructive-command guard: new PreToolUse hook `guard-destructive.sh` with a builtin pattern set and project `careful.patterns`; denies with a single-use, 10-minute approval code that only the user's own message (`onay <code>` / `approve <code>` at its start) can grant; Edit/Write to the grant file are denied too. `MEMOKIT_CAREFUL_OFF=1` disables it; SessionStart warns about invalid project regexes; `/memokit:init` writes an empty `careful.patterns`.
- `/memokit:triage`: bulk triage of red/flaky tests into REGRESSION / FLAKY / ENV/DATA / UNKNOWN clusters with evidence, then root cause with a three-strike stop and a red-before-green fix slice; overlay `.claude/memokit/triage.md`; the debugging hint points to it.
- Decision format in WORKING-MODEL.md §2 (recommendation, stakes, one-way/two-way door, options, completeness); the rule block, `memokit:coder` and `/memokit:triage` use it.
- `memokit:coder` reports a bugfix slice's red output from before the fix; `memokit:reviewer` rejects a bugfix slice without it.
