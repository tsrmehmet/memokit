# Changelog

Every change to `hooks/`, `skills/`, `agents/` or `WORKING-MODEL.md` bumps `version` in `.claude-plugin/plugin.json` and adds an entry here (a pinned version means `/plugin update` delivers nothing otherwise).

## 0.8.1 — 2026-11-12
Flow hardening after 0.8.0: `/memokit:resume` proposes parallel runs, `/memokit:handoff` waits for live agents, subagents lose the last easy ways to touch settings and memokit's own state, and the test suite stops littering the real temp dir. Nothing here needs a config change; `parallel.auto`, `review.validate` and `convert.markitdown` are the only new keys (`hints.builtin` also accepts `context7`).

### Flow
- **`/memokit:resume` proposes `/memokit:parallel`** when two or more tasks remain in the work STATE points to and `parallel.maxCoders` is above 1. The offer sits in the confirmation step next to "one at a time"; resume does not dispatch an analyst to judge independence (the parallel plan table is what you approve). One task, `maxCoders: 1` or a talk-first stamp: no proposal.
- **`parallel.auto`** (boolean, default `false`; schema and `examples/memokit.json` updated): with `true`, resume announces in one sentence and starts `/memokit:parallel` itself instead of offering it. Plan approval and the decision sweep inside the parallel skill still happen.
- **Parallel runs measure themselves**: the ledger records the slot wait and wall time of each lane (concrete ISO-8601 stamps) and the run report ends with a measurements block.
- **PDF and Office files as Markdown (opt-in)**: with `convert.markitdown: true` (boolean, default `false`; schema and `examples/memokit.json` updated) and the `markitdown` CLI on PATH, the new PreToolUse hook `convert-read.sh` redirects a Read of a `.pdf`, `.docx`, `.pptx` or `.xlsx` file without a `pages` argument to a cached Markdown conversion (`updatedInput`, one line of context). Scanned PDFs (under 200 non-blank characters per page), empty results, failures and conversions over 45 s leave the Read alone; any `Read` deny or ask rule in a settings file the hook can see (project, launch directory, current directory, user, managed and `managed-settings.d`) keeps the hook out. A file outside the launch directory is redirected with an "ask" naming the original path; each document is cached in its own directory (SHA-256 and size of its content). The cache (`memokit-<n>-careful-convert` in the temp dir) is protected memokit state, so a subagent cannot plant Markdown for the next Read of a document: a subagent Write/Edit below it is denied (also through a symlink or hard link) and a Bash command naming it is `careful-state` (main session too; the cached copy is read with Read only). A cache hit counts only when the cache dir, the document's dir and the copy are yours and not symlinks; anything else is converted again in a fresh dir or left alone. A process running as you can still replace an entry through an indirection the guards cannot see (README "Known gaps"). `/memokit:init` offers the setting only when markitdown is installed and otherwise names `uv tool install 'markitdown[pdf,docx,pptx,xlsx]'`.
- **`/memokit:handoff` waits for running agents** (background agents, background shells, dev servers): their reports are folded into STATE before the handoff is written, and dev servers still running are listed.

### Agents
- **Four rules from the Karpathy guidelines** in `memokit:coder` and `memokit:reviewer` (only the speculative-code rule is also in WORKING-MODEL §8): surgical changes (no neighbouring clean-ups; remove only what your own change made unused; a comment your change makes wrong is part of the slice), no silent interpretation (two readings that lead to different code are a `NEEDS_DECISION`, trivial choices go under `Assumptions:` in the report), no speculative code (no unrequested option, flag or configurability, no error handling for a case that cannot happen), and the reviewer rejects a changed line that does not trace to the slice, with `file:line`.

### Hardening
- **Window push options are an allowlist.** git accepts option prefixes, so a denylist missed spellings. Inside a change window a `git push` option outside `-u --set-upstream -f --force --force-with-lease --force-with-lease=* --force-if-includes -q --quiet -v --verbose -n --dry-run --tags --follow-tags --atomic --no-verify --progress --no-progress --porcelain -o/--push-option <value> --push-option=*` is not covered. **User-visible:** unusual push options (`-4`, `-6`, `--thin`, `--signed`, `--recurse-submodules=…`) now ask for a code inside a window. A window also never covers a push that deletes or mirrors refs.
- **Settings files are protected from subagents**: `.claude/settings.json` and `settings.local.json` of the project, `~/.claude/settings*.json` and the same under `CLAUDE_CONFIG_DIR`. Writes by any spelling the guard can read are denied: redirections, `cp`/`mv`/`tee`/`sed -i`, interpreters, globs and expansions that can name the file, dotfile and symlinked paths (physical resolution before `..` folding; a link made in the same command fails closed), commas, `~user`, and a cwd inside a settings directory. **User-visible:** a subagent can no longer read settings files or `memokit.json` through `git diff|log|show|status` or `sed` (git subcommands left the read-only allowlist: `diff.external`, textconv and pagers make "read-only git" unprovable); `cp x $OUT/settings.json` is denied for subagents (an expansion word that could name a settings file is a hit); `2>/dev/null` and `2>&1` on reads still pass.
- **State expiry caps and computed writes.** A pending or window record whose expiry is later than now plus its time to live (600 s for codes) is malformed and removed on read. A write into `memokit-` state paths that the shell computes is `careful-state` (never approvable), also past 64 KiB and after redirections; when a command carries no temp path at all, a computed write only asks for a code. **User-visible:** release-style commands such as `npm pack > memokit-$v.tgz` ask for a code.
- **Session-start config snapshot for subagent hooks.** SessionStart (startup, resume, clear) copies the validated `.claude/memokit.json` to a per-session file; guards judge subagent calls by that copy, so a subagent that edits the config gains nothing during the session. The main session keeps using the live file. When the file changes or disappears mid-session, the next prompt shows one notice; `/clear` or a new session adopts the change. A failed snapshot write or an invalid config removes the session's snapshot, and hooks fall back to the live file. Subagents cannot re-run `session-start.sh` (text only: a word whose last path component is `session-start.sh`, or a glob or expansion that could match it such as `hooks/*start.sh`, `${D}start.sh` or `sess*`, wherever it points; a `$(` or backquote together with `start.sh` or `session` anywhere in the command is a hit too; `$ROOT/scripts/start.sh` passes; and the script neither writes nor deletes the snapshot under `CLAUDE_CODE_CHILD_SESSION=1`). This is one more layer, not a tamper-proof one: the snapshot is a same-user file in the temp dir.
- **State-file pruning.** SessionStart removes memokit state files (`careful-*` and friends) older than 7 days, in the background, at most once a day. The stamp file is written with the safe writer; a stamp that is not a regular file of yours, or dated in the future, does not block pruning.
- **README "Known gaps" extended** with the residual lexical classes (see there). The runtime check below now covers what the text check cannot see.

### Plugin-file protection
- **Subagents may not write memokit's or other plugins' installed files**: `~/.claude/plugins`, `CLAUDE_CONFIG_DIR/plugins` and `CLAUDE_PLUGIN_ROOT` (also spelled `$CLAUDE_PLUGIN_ROOT` / `${CLAUDE_PLUGIN_ROOT}`, a glob or expansion word that can name one is a hit). File-tool writes, Bash writes, file symlinks and relative link targets are followed. **User-visible:** a subagent that edits an installed plugin is denied.
- **Project-tree exemption for development**: when memokit runs with `--plugin-dir <project>` on its own checkout, writes inside the project tree are ordinary. The exemption needs `CLAUDE_PROJECT_DIR` set and resolving to the project, physical paths and case-exact names; a plugin root inside the project, an installed cache or a project under `~/.claude/plugins` never gets it. Dogfood side effect: in such a session a subagent command that holds a glob or expansion and is not read-only (`bats tests/*.bats`) is denied; only exact project spellings pass.
- **Subagents may not file-write memokit state**: Write/Edit/MultiEdit/NotebookEdit on a `memokit-<n>-careful-*` temp file, or anywhere below a `memokit-<n>-careful-*` directory (the markitdown cache), is denied, and so is a write through a hard link to one (the check denies on any `memokit-*` name directly under the temp dir, or one or two levels inside a `memokit-<n>-careful-*` directory, that has the target's inode).

### Runtime integrity check
- **`check-integrity.sh`** (PreToolUse on every tool; PostToolUse, PostToolUseFailure and SubagentStop for subagents) records a stamp of the protected set before each subagent tool call and compares it afterwards: the settings files of the project, user and `CLAUDE_CONFIG_DIR`, `.claude/memokit.json`, the session's config snapshot, and the plugin root's files (`tests/` and `.in_use/` are skipped; `.git/config` and `.git/hooks/` are included). A stamp is checksum, executable bit, symlink flag, inode and change time (ctime), computed by one `find`, one `cksum` and one `stat` pass; a directory, or a symlink to one, is stamped by inode and change time alone (no checksum), so an unchanged link to a directory never alerts; such a link also carries its link text (a retarget shows), and one that resolves outside the plugin root, or into an area the check skips (`tests/`, `.in_use/`, `.git/` but `.git/hooks/`, the exempt project tree), alerts on every call, since the files behind it are not checked.
- **It reports, it does not restore.** On a change the subagent's call is blocked with the file names (fixed labels, plugin files as relative paths, at most 10 then "+N more") and a stop-and-report instruction; the orchestrator's **next tool call is denied once** with the same list; the **next prompt carries a notice**. **User-visible:** after a subagent changed a protected file, one orchestrator call is denied and nothing else; the user decides whether to keep or revert. A digest failure, a timeout or a missing record for an agent that already has a baseline counts as a change (`?`).
- **SubagentStop baseline**: each agent's first call writes a baseline (and an armed stamp); SubagentStop compares against it, so a change made between calls is still reported (the stop itself prints nothing), and the baseline is renewed after a report.
- **Allow-only notice**: if the only difference is added `permissions.allow` entries in a settings file and a PermissionRequest hook (`record-permission.sh`, records only, never allows or denies) recorded a prompt while that call ran (same rule, a destination that writes that settings file, between the call's Pre and Post; the prompt may come from a parallel call of the agent, so the hook matches Bash, Edit, Write, MultiEdit, NotebookEdit, Read and WebFetch; a record backs every call whose window holds it, so parallel lanes see the same prompt, but only for one change: it is bound to the settings file's stamp after that change, so a second edit or the rule removed and added again is the full alert; records expire after 10 minutes; the record file is read, checked and rewritten under a lock, and a lock not taken within about 1 s is the full alert), nobody is blocked or denied: the next prompt lists the added rules, which is what "Yes, and don't ask again" writes. Broad Bash rules backed by such a record (a `*` inside the command, or a first word that is a shell, interpreter, wrapper or arbitrary-exec command: `python3`, `env`, `find`, `awk`, `sed`, `npx`, `ssh`, `tar`, ...) and bounded `Edit`/`Write`/`Read` patterns and `WebFetch` domains with a `*` (`Edit(src/**)`, `Write(docs/*.md)`, `Read(src/**)`, `WebFetch(domain:*.example.com)`) are not blocked either: they get a notice of their own (`IG_BROAD_NOTICE`) that names them and asks the user to confirm them. Rules naming `.claude`, settings, memokit, plugin paths or `CLAUDE_CONFIG_DIR`, and unbounded ones (bare tool names, wildcard-only patterns such as `Bash(*)`, `Edit(**)`, `Edit(~/**)`) are always the full alert, record or not, and the baseline is kept so SubagentStop reports them again. Prefix rules for ordinary commands (`npm run test:*`, `git status`, `make build:*`) get the plain notice. Without a record any added rule is the full alert. SubagentStop never takes the exemption.
- **Measured** (median of 21, macOS `/bin/bash` 3.2, wall/CPU ms): installed shape (60 files, 0.87 MB) Pre 38/34, Post 44/41, first Pre 52/46, SubagentStop 36/34; a worktree as plugin root (95 files, 1.7 MB) Pre 45/41, Post 51/48, first Pre 56/51, SubagentStop 47/45; main-session fast path 4/3, the same with 200 000 entries in the temp dir (mean of 100: 3.3-3.9/2.8-3.3, of which bash's own start is 2.6-3.2; the alert marker has a root-independent name, so the fast path is one file test where a glob over that temp dir cost 390 ms per call); PermissionRequest hook 29 ms.
- **Residuals** are listed in README "Known gaps" (same-user tampering with records, changes that outlive a subagent, background Bash, a permission record proves a prompt, not the "don't ask again" choice).

### Review verdicts and validation
- **Per-finding verdicts**: `memokit:reviewer` marks each finding `confirmed` (severity by impact), `needs_validation` (with the `blocker`: the measurement that would settle it) or `rejected`; `REJECT` only for a `confirmed` finding, and a security finding without principal, boundary and observed result is `needs_validation`.
- **Findings JSON and `memokit-findings.sh validate <report>`** (jq only): checks the last fenced `json` block (unique ids, integer lines, severity iff confirmed, blocker iff needs_validation, a `REJECT` needs a confirmed finding); a malformed report is re-run once.
- **`review.validate`** (`high` default, `always`, `never`; schema and example updated): after a `REJECT` a second reviewer is given only the findings and the diff and tries to refute each finding. Refuted findings drop out; the fix round runs on the surviving ones. New lane state **`validating`**: open `needs_validation` items are measured before the lane may merge (a user deferral is recorded in the ledger and STATE).
- **`/memokit:triage` guidance mode**: a question with no source is answered from evidence already present (read-only look-ups count), with the same four classes; no tests, no files; it names the source that would let the other modes confirm.

### Learn, stats, hints
- **`hooks/lib/transcript.sh`** is the one transcript reader (line-by-line parse, half-written last line dropped, split assistant records counted once per message id); `check-context-budget.sh` uses its tail reader.
- **Handoff prints one session stats line** (`memokit-stats.sh`): context at the end, output tokens, tool calls (top 5), hook denies, subagent dispatches; no currency. The transcript is found by session id, with the newest `.jsonl` of the project as fallback (the pick is named on stderr).
- **`/memokit:learn`** mines the session for hook denies, tool errors, your corrections and repeated commands, proposes at most 5 short rule lines and writes only the lines you approve (`rules.md`, at most 1.5 KB, or `docs/LESSONS.md`).
- **context7 hint** (`hints.builtin`: `context7`): a prompt about a library, framework or API version (including `sdk` followed by a version number) gets one line telling the AI to look up current docs with context7 when available. All builtin and custom hint patterns now match ASCII case-insensitively under any locale (grep runs under `LC_ALL=C` first, so an upper-case `I` matches under `tr_TR.UTF-8`) and fall back to the user's locale for Turkish upper-case letters (`ÇALIŞMIYOR`).

### Tests
- **Private `TMPDIR` per test**: the suite no longer leaves `memokit-<hash>-*` state files in the real temp dir (a hygiene test checks the fixture project's hash).
- **`careful-remote.bats` split** by section into `careful-remote-labels`, `-rounds-1-2`, `-rounds-3-5`, `-bounds` and `-final`, so one area re-runs on its own. Measured at the split: the original file 2:29, now 0:20 / 0:31 / 1:16 / 0:14 / 0:19. The split is for per-area runs, not a sequential speed-up.
- Every new match on the command text has a 64 KiB timing test under `tr_TR.UTF-8` (only when `locale -a` lists it), bound 2 s of the hook's CPU time (user+sys, children included; wall time is printed alongside; the heaviest payloads take 750-970 ms on an M4 Max, and 2 s is half the hook's own 4 s CPU budget), so machine load does not flake them.

## 0.8.0 — 2026-11-11
Remote changes inside an approved change window, and code-free cleanup of the orchestrator's own temp dirs and finished lane worktrees. Part A is opt-in per project (a `remote` object in `.claude/memokit.json`); without it nothing in "Remote changes (Part A)" is active.

### Remote changes (Part A)
- **`remote` config** (user decision, 2026-11-10: "sunucuda onayım olmadan hiç bir değişiklik yapmaması lazım", read-only free, one approval for the whole deploy, report any failure): `remote.deployBranches[]`, `hosts[]` (`"*"` = every host), `readOnlyFirstWords[]`, `windowMinutes` (30, 1-240), `runbooksDir` (`.claude/memokit/runbooks`), `log` (`docs/DEPLOYS.md`); schema and `examples/memokit.json` updated. `careful.patterns[]` gets an optional `target`, so flyctl, vercel or ansible patterns can be covered by a window.
- **Four builtin labels with targets**, per segment on every view, only under `remote`: `deploy-push` (`git push` naming a deploy branch or with no refspec when the current or upstream branch is one; `gh pr merge` and `gh workflow run` count for every deploy branch), `remote-mutate` (`ssh`/`scp`/`sftp`/`rsync` to a configured host), `k8s-mutate` (`kubectl apply|create|…|cp`, `helm install|upgrade|rollback`), `runbook` (a file under `runbooksDir`, with its sha256 in the plan). Read-only exemptions: a one-segment `ssh` command whose first word is in the builtin list (`cat ls ll head tail wc df du free uptime whoami id printenv stat grep egrep fgrep ps netstat dig nslookup test true echo pwd which type file md5sum sha256sum systemctl-status systemctl-is-active systemctl-list-units docker-ps docker-logs docker-inspect docker-images docker-stats docker-compose-ps kubectl-get kubectl-describe kubectl-logs kubectl-top git-status tmux-ls`) or `readOnlyFirstWords`, `ssh` with no remote command only with `-N`, `-G`, `-V`, `-Q` or `-O check|exit`, `scp`/`sftp`/`rsync` downloads and `rsync --dry-run`, `kubectl diff` and `--dry-run=client|server`, `git push --dry-run`.
- **Deviations from the spec** (review rulings, kept): `less env date find curl wget top htop ss ip ifconfig hostname journalctl git-log git-diff git-show` are not read-only (they can change the server or run another program; `ssh prod env` needs a window); `ssh -T` with no remote command is not exempt (it opens a shell); `kubectl delete` and `helm uninstall|delete|del|un` keep their own labels and carry a `k8s` target; pending codes and windows belong to one session (`careful-pending-<session>`, `careful-window-<session>`), not to the project: a second session in the same project gets its own deny; a covered command passes a window only up to 20 segments (`MK_GD_MAX_STRIP`), a longer one gets the plan deny with a shape hint.
- **Change plan and window**: a labelled command is denied with `CF_REMOTE` (a CHANGE PLAN template in the project language: targets, what changes, rollback, verification, dry-run output, no command list). `onay <code>`, `onaylıyorum <code>`, `approve <code>`, `approved <code>` or the bare `onay`/`onaylıyorum`/`approve`/`approved`/`evet onayla` (grants the single unexpired pending code) opens a window for the plan's targets; the grant message names them and the expiry. A pass covers the four labels for the window's targets plus every other label in the same segment; a local segment in the same command, a target outside the window and a subagent stay denied. A background command in a window is denied (`CF_REMOTE_BG`).
- **`hooks/memokit-window.sh request <target>…`**: one code for a plan with several targets (`host:<name>`, `branch:<name>`, `k8s[:<context>]`, `runbook:<path>`, `pattern:<target>`); unknown targets exit 2 and list the allowed ones. Refused for subagents.
- **`close-window.sh`** (PostToolUse and PostToolUseFailure, Bash): a command that passed through a window is marked; when it fails the window closes and the next deny is `CF_REMOTE_FAILED` (report, agree the next step, new window, no improvising). Measured on Claude Code 2.1.322 (2026-11-10): a non-zero Bash exit fires only `PostToolUseFailure`, whose payload has no `tool_response` and no numeric exit field (the status is the first line of `error`, `Exit code N`); a zero exit fires only `PostToolUse`; no Post event reports the failure of a background command.
- **Subagents** never pass a remote label or run `memokit-window.sh`, whatever window is open (`GS_REMOTE`, `GS_WINDOW_REQUEST`); they cannot write `.claude/memokit.json`. Pending and window files join the protected state files (`careful-pending`, `careful-window`), never approvable, Edit/Write denied.
- **WORKING-MODEL §10 "Remote changes"** and README "Remote changes": read-only is free, one approval per plan, a failed step stops the plan, verification measured and one `remote.log` row, never hand the user a command.
- Measured (2026-11-10, before this release): the 0.7.2 guard denied only force-push, `reset --hard`, recursive rm, `kubectl delete`, `helm uninstall`, `docker prune`, destructive SQL and project patterns; a plain `git push origin deploy` or `ssh host 'cmd'` passed `guard-destructive.sh` for the orchestrator, and in the builder-check project `Bash(ssh *)` was already allowed. The hand-back to the user was model behaviour, not a guard.

### Code-free cleanup (Part D)
- **Temp dirs** (user decision: "orkestratör … direkt silebilsin"): the main session's recursive `rm` of the session scratchpad or a whole stale sibling temp entry passes inside a chained or quoted command, when every target is a literal absolute path and every other part of the command is `cd <literal path>`, `echo`, `printf`, `true`, `false`, `:`, `test`, `[`, `ls` or `pwd` (positive allowlist, no parentheses or backticks, at most 16 targets). `cp`, `mv`, `ln`, `rsync`, `tar`, interpreters and anything else keep the code (`mv <outside> <scratchpad>/x && rm -rf <scratchpad>/x`). Subagents keep the single literal `rm -rf`. `CF_SCRATCH_HINT`, `lib/temp.sh` and WORKING-MODEL §7 say exactly this.
- **Lane worktrees and branches** (main session only): `git worktree remove [--force] <path>` and `rm -r <literal path>` pass for a worktree that `git worktree list` shows, that is not the main checkout, contains neither the cwd nor an excluded directory, and is `merged-clean` (branch merged, no uncommitted change; ignored files do not block); `git branch -D <name>` passes when the branch is merged into the default branch or HEAD and no worktree checks it out. Dirty, unmerged, active-run, nested-worktree and error cases ask for a code. Git calls of these checks are bounded (1.5 s each, `_MK_WT_SECS`). Needs git 2.36 or later (`git worktree list -z`); with an older git every lane removal asks for a code.

### init
- `/memokit:init` asks whether the project deploys through pushes or servers and, on yes, writes the `remote` block (`init remote-config`: branches, hosts, `runbooksDir` validated), creates `runbooksDir` with a README, and offers narrow `Bash(ssh <host> *)` / `Bash(git push origin <branch>*)` allow rules for the git-ignored `.claude/settings.local.json` (`init allow-tools` accepts only those two shapes).

### Fixes
- The `rm` recursion check no longer hangs on long quoted commands: bash 3.2 pattern substitution on long quoted commands under a UTF-8 locale could run for hours; the guard was then killed and the command ran unchecked — replaced by one regex.
- **Every PreToolUse guard has a hard time budget** (final review C1, C2): `guard-subagent-authority.sh` and `guard-edit.sh` had none, and cheap commands (eight brace groups, 16 000 `<<1` lines, 1 000 `ls ../x` lines, 20 KB of `echo $x` lines) kept them busy for 14 s to minutes; after Claude Code's 5 s timeout the command ran unchecked. The budget of `guard-destructive.sh` (a 3.3 s wall-clock watchdog, a 4 s CPU limit, a deny printed exactly once) moved into `hooks/lib/budget.sh` and arms all three guards (`GS_BUDGET_STATIC`, `GE_BUDGET_STATIC`; a crash denies). The hot spots are gone: heredoc bodies are stripped by one awk pass (it forked `grep | tail` per `<<` line), the subagent config gate de-duplicates and filters its word lists before any bash loop, folds `..` paths in one awk and tests device:inode with one `xargs stat`, brace expansion is computed without `eval` (more than 64 alternatives in a word, more than 1 024 in a command, a letter range or a nested brace: a config reference), `bash -c` extraction and the first-line cut use awk and sed, and `_mk_rm_bare` is one regex (it stripped one character per pass, 1.2 s for 4 KB of `)`). New bounds deny as too large: a subagent command over 64 KiB or with more than 512 words holding `..`, a dollar sign or a backquote, or brace expansions (`GS_TOO_LARGE`); a main-session command naming more than 64 distinct write targets (`GE_TOO_LARGE`). Measured under `tr_TR.UTF-8`: every payload of the review decides in under 0.6 s.
- **`grep 'foo$' file` is no longer denied as `unparsed` with `remote` configured** (C3): the ANSI-C decoder treated the `$'` of a quoted `…$'` as an opening `$'…'` span; it now tracks quotes and opens a span only outside quotes and when the `$` is not escaped.
- **Remote labels** (I1-I4): with `hosts: ["*"]` a destination the shell computes (`ssh $H`, `ssh "$H"`, `root@$H`, `$(cat h)`, `${H}`, a `*`/`?` glob) is the target `host:(computed)`, which no window holds (ordinary code); `git subtree push`, `git http-push` and `git p4 submit` are pushes; `NAME+=value` before `git` ends the dry-run exemption like `NAME=value`; the ANSI-C decoder handles `\u`, `\U`, `\a \b \e \E \f \r \v \?`, ends the string at a NUL as bash does (`$'prod.example.com\0x'` is `prod.example.com`) and fails closed on `\c` and unknown escapes.
- **Subagent `Write` of `x/missing/../y.txt`** (I7) is no longer denied: the path is folded lexically first and only its longest existing prefix is resolved physically.
- **Config validation** (I8, M1): `remote.runbooksDir`, `remote.log` and `guardedDirs` refuse a `.git` segment at any depth and in any case; `remote.hosts` entries must hold no blank or newline; `remote.windowMinutes` must be an integer. `init allow-tools` refuses a host or branch starting with `-` and a branch holding `..` (I9).
- `Edit`/`Write` of `careful-active-*` is denied like the other state files (M2).
- **Project patterns with a target**: a command that names no builtin tool, host or deploy branch (`flyctl deploy --app x` in a project without a `deploy` branch) got its pattern label but not its `pattern:<target>`, so no window could cover it; such a command is now matched against the target patterns. ## 0.7.2 — 2026-11-04
- **Destructive-command guard: the `rm-recursive` exemption is byte-wise and exists only in C/POSIX/UTF-8 locales** (security review round 5): in a double-byte locale (zh_TW.Big5, zh_CN.GBK, GB18030) a lead byte followed by a backtick is one character, so the exemption's bracket class swallowed the backtick and ``grep x `$RM -rf y` `` looked exempt. The exemption regex and the single-segment test (`_mk_cf_oneseg`, whose case patterns a double-byte lead byte could swallow a `|` in) now run under `LC_ALL=C`, and the exemption is only possible when the effective `LC_CTYPE` (first non-empty of `LC_ALL`, `LC_CTYPE`, `LANG`) is empty, `C`, `POSIX` or a UTF-8 locale; in any other locale nothing is exempt and the 0.7.1 rule runs over every view (accepted false positive, an approval code is asked). No other stage changed locale behaviour.
- **Destructive-command guard: fewer `rm-recursive` false positives** (from a user project's backlog, BL-449). The computed-command-word rule (`$RM -rf x`, `"${RM}" -rf x`, `/bin/r? -rf x`) matched any word holding `$ * ? [..]` followed by an `-r`/`-R`/`--recursive` option, so read-only commands were denied as a recursive rm: `grep -n "Send.*Key" -r tests`, `jq '.items[]' -r f.json`, `ls tests/*.cs -R`. The rule is unchanged (a computed word followed by a recursive option anywhere in a segment is `rm-recursive`, fail closed, as in 0.7.1) except for a narrow allowlist. A command is exempt only when ALL of this holds: (1) it is one segment in every view, i.e. it has no `;`, `|`, `&&`, ` & ` or newline anywhere, quoted or not, and the RAW text is a single line with no newline at all, backslash-continuation lines included (a continuation line is never exempt; the locale gate checks the locale name, but bash can fall back to LANG's charset when LC_CTYPE names a locale that does not exist, e.g. `LC_CTYPE=en_US.utf8 LANG=zh_TW.Big5`, and a double-byte charset can change where a continuation line ends; without a newline there is no separator for it to hide) (quotes are not parsed, and a separator inside quotes would fake a segment starting with `grep`: `X="a;grep x" $RM -rf y`); (2) its FIRST word is exactly `grep egrep fgrep jq ls cat head tail wc diff cp` (bare name: `grep()`, `/tmp/grep`, `grep2`, `"grep"` and `/usr/bin/grep` are not exempt; a leading `NAME=value` is not skipped, so `LC_ALL=C grep ...` is still denied); (3) it holds no backtick, `(`, `)`, no backslash and no `<`, `>` or `&` at all (redirections are never exempt: an exemption that modelled them was fooled by escaping, `grep x a\>&"$RM" -rf y` runs `"$RM"` as a background command because `\>` is a literal and `&` the background operator; accepted false positive: `grep x $D -r >out`), and every `$` in it is followed by a letter or `_` (plain `$NAME` or `"$NAME"`; so no `${..}`, `$[..]`, `$((..))`, `$(..)`, `$'..'`, `$".."`, `$1`, `$@`, `$=x`, `$~x`, `$$` or trailing `$`, which can run code, e.g. `grep x ${z:="a[\$(…)]"} $[z] f` through arithmetic expansion, or spell any option). What was checked (measured on macOS, 2026-11-04): the macOS/BSD man pages/help of grep, jq, cp, head, tail, wc, cat, ls and diff were scanned for an option that runs a program (`diff --paginate` runs only `pr`); the GNU variants were not measured and are documented to have no such option. `cp --remove-destination` replaces a destination file by the source. `yq` is not on the list (mikefarah yq v4 has a `system` operator behind `--security-enable-system-operator`; python yq runs `jq` from PATH). There is no option blacklist: commands that can run a program are simply not on the list. Earlier 0.7.2 drafts exempted `tar`, `git grep|log|diff|show` and `rg` with a blacklist of their command-running options, and option names built with `${u}`, brace expansion or quoting (`tar -${u}-to-command=$RM`, `rg -{-pre=$RM,n}`) got through; `sed` (`e`), `awk` (`system()`) and `ag` (`--pager`) run commands too. The exemption is decided once, on the raw command text as a whole (one bash regex test, no fork; when it holds the computed-word rule is skipped, otherwise the plain 0.7.1 rule runs over every view). The flat view takes no part: it deletes quotes, backslashes, parentheses, braces and backticks, the very characters that disqualify, so a per-line exemption let ``grep x `$RM '' -rf y` `` through. Why not a command-position rule: a first draft anchored the computed word to the command position with a wrapper list and missed `case x in a)$RM -rf y;; esac`, `function f { $RM -rf x; }` heads and wrappers it did not list (`gtimeout`, `pkexec`, `fakeroot`, `busybox`, `$SHELL -c ...`), which 0.7.1 caught; it was dropped before release. Accepted false positives (they ask for an approval code): pipelines and lists (`git ls-files | grep -n "x.*" -r`), parentheses (`grep -rn "func(.*)" -r .`, `grep -nE "^(foo|bar)$" -r src`), a `$` right before a quote (`grep -n 'x$' -r src`), a `$` followed by anything but a letter or `_` (`grep -n "${p}" -r src`, `grep -n "x$" -r src`), an assignment prefix (`LC_ALL=C grep ...`), absolute paths (`/usr/bin/grep`), `yq`, `sed`/`awk`/`ag`, and `tar`, `git grep|log`, `rg` (`tar -C "$d" -rvf a.tar`, `git grep -n "a.*" -r`, `rg "a.*b" -r x f`). README Limitations updated.

The guard checks labels in bash (a broken grep no longer reads as "no careful-state"), validates jq's deny and config output, and a tr or grep that fails or prints nothing gives careful-state. More spellings: wrapper `-n` (`nice -n 10 git clean -fdx`), command names in any case or with `.exe` (`RM -rf x`, `Git push -f`, `kubectl.exe delete`), `dropdb`, `mysqladmin … drop`, `pgcli`; `__pycache__` and `.pytest_cache` join the rm safelist. `git clean -f` is labelled even with `-n`/`--dry-run` (an option argument such as `-e -nx` read as a dry run let `git clean -fdx -e -nx` through). The grant-file check is case-insensitive and glob-aware: the name (`CAREFUL-GRANTS`, `careful?grants`, `careful*grants`) is never approvable, nor is a glob on a temp-located `memokit-` path (`/tmp/memokit-*`, `$TMPDIR/memokit-*`); other globs (`careful*`, `../memokit-*`) are the approvable `careful-state-glob`; every deny message lists all labels; and each awk/sed stage must echo a per-call sentinel line, so a tool printing plausible but constant output fails closed. The temp exemption skips commands over 4 KiB (1 KiB with a line continuation), which removed a quadratic slowdown that let the guard run past its 5 s timeout on 64 KB of continuations.
- Known false positives (accepted, ask for approval): quoted text is matched like a command (a commit message mentioning `git push --force` now asks too), and `"$EDITOR" -R file`-style computed words before an `-R`/`-r` option. Still out of reach (README, Limitations): `$X push -f`, `$(printf %s r m) -rf x`, `/bin/r(m|x)`, `$RM src -rf`, `DROP${IFS}TABLE`.
